# IMU / UM982 监视上位机

Windows 下双击 `tools/start_monitor.bat`，或在工程根目录运行 `python tools/monitor_gui.py`。若未安装串口库，先运行 `python -m pip install -r tools/requirements.txt`。本机已安装 pyserial 3.5。USART6 PC6 接 USB 转串口 RX，接地；选择对应 COM 口后点“连接”。波特率固定为 921600、8N1。

界面实时显示 G365 的帧率、COUNT、FLAG、角速度/加速度，UM982 的位置解类型、精度与卫星数、双天线航向和基线，以及固件 `S` 计数、PC 行损坏和 MCU/GPS 时间漂移。新版 V2 日志还显示 PPS 捕获次数与周期、DRDY 捕获和未配对 IMU 帧数。两幅曲线保留最近 30 秒的位置、航向标准差。点击“开始保存原始日志”可随时保存串口原始字节；包括未就绪阶段，便于诊断。选择“回放日志”可按日志中的 `mcu_ms` 速度重放；也可运行 `python tools/monitor_gui.py --replay 路径`。`--analyze 路径` 在命令行输出简要结果。

默认“可开始采集”需要：IMU 近 3 秒约 200 Hz、两路 GNSS 消息新鲜、位置与航向均为 `SOL_COMPUTED / NARROW_INT` 且 GPS 时间 `FINE`、位置水平标准差不超过 0.20 m、高程标准差不超过 0.5 m、航向标准差不超过 2°、最近 5 秒航向基线变化不超过 0.1 m，且位置/航向连续稳定 5 秒、没有最近 5 秒的日志/固件链路错误。水平与航向阈值可以在界面修改，实测天线基线长度可选填；填入后还要求与报告基线相差不超过 0.1 m。这些数值是保守的采集门槛，按实际安装和精度目标调整。

“可开始采集”只表示**原始传感器采集条件**，不表示组合导航滤波器收敛。V2 固件把 IMU DRDY 与 GNSS PPS 捕获在同一个 TIM2 时基，并记录 UART 字节到达时刻；若 PPS 捕获超时、周期无效、捕获队列出错，或 `A` 行尚未连续建立 GPS 整秒配对，界面不会显示就绪。GPS 整秒归属仍依赖 UM982 消息延迟和 PPS 极性的核对，需用 `tools/time_sync_report.py` 和实测波形检查。

固件和上位机现在均按本次 200 Hz 数据的 COUNT 正常步长 312/313 检查跳帧。`test1.txt` 中有一条 GNSS 与 IMU 日志拼接损坏，上位机将其计为记录错误。若串口上位机处理队列溢出，也会使就绪条件暂时失败。
