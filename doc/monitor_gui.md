# IMU / UM982 监视上位机

Windows 下双击 `tools/start_monitor.bat`，或在工程根目录运行 `python tools/monitor_gui.py`。若未安装串口库，先运行 `python -m pip install -r tools/requirements.txt`。本机已安装 pyserial 3.5。USART6 PC6 接 USB 转串口 RX，接地；选择对应 COM 口后点“连接”。波特率固定为 921600、8N1。

界面实时显示 G365 的帧率、COUNT、FLAG；模式 3 显示六轴原始整数、角增量（°）和速度增量（m/s），模式 2 显示角速度/加速度。还显示 UM982 的位置解类型、精度与卫星数、双天线航向和基线，以及固件 `S` 计数、PC 行损坏和 MCU/GPS 时间漂移。新版 V2 日志还显示 PPS 捕获次数与周期、DRDY 捕获和未配对 IMU 帧数。两幅曲线保留最近 30 秒的位置、航向标准差。点击“开始保存原始日志”可随时保存串口原始字节；包括未就绪阶段，便于诊断。选择“回放日志”可按日志中的 `mcu_ms` 速度重放；也可运行 `python tools/monitor_gui.py --replay 路径`。`--analyze 路径` 在命令行输出简要结果。

## 增量采集

新版板端启动先做连续 3 秒有效静止统计，期间 USART6 无输出，属于正常状态；有运动/丢帧会重新计时。采集器可以先连接并开始保存，保持静止直到看到数据。收到 `B` 后显示标定时长、样本数和三轴静止均值，并在模式/比例一致且有有效 DRDY 时间间隔时另行显示“去静止均值 Δθ”；模式 2 显示去均值角速度。原始 `I` 行和原始量显示不变。静止均值包含地球自转，补偿后的显示量不能替代 KF-GINS 的原始增量输入。`B` 原样写入日志，配套 JSON 同时保存最新一次 `startup_calibration`；与采集配置冲突时不显示就绪。

补偿显示使用最近完整配对的 `I/T` 帧：下一条 `I` 已到、对应 `T` 尚未到时，保留上一组完整帧，避免界面刷新恰逢两行之间而闪烁，不将上一帧时间间隔套用到新数据。补偿行始终保留；配对失败、配置冲突或完整帧超过 0.2 秒未更新时显示原因。此缓存仅用于显示，不改变原始日志、就绪检查或板端标定。

1. 编译并烧录默认模式 3 的固件，确认日志 `I` 行第三个字段为 `3`、IMU 约 200 Hz。物理传感器输出必须与固件模式相同；相同帧格式无法自动判断传感器寄存器设置。
2. 上位机期望模式默认 `3`。读取传感器实际 `DLT_CTRL`，按十六进制填入，然后勾选“已核对传感器实际寄存器”。新采集默认 `0x0048` 是待配置的动态采集值，必须先配置物理传感器；不代表设备已经修改或每次采集都自动核实；未勾选时换算仅供预览。界面不会写传感器或 MCU 配置；板端调试浮点量也需使用同一比例，原始整数日志不受比例设置影响。
3. 保存期间锁定本次配置。模式不符、同一连接混入模式 2/3、比例未核对、近 5 秒有 FLAG 传感器错误/超量程时，不显示就绪，但仍可保存诊断数据。切换物理模式后重新连接并另存一段日志。
4. `name.txt` 保存收到的全部原始字节，不插入说明或配置、不将增量再乘采样间隔。界面丢显示记录不会改变写盘数据，但串口/磁盘错误仍需处理。配套 `name.txt.capture.json` 单独记录人工声明的模式、200 Hz、DLT_CTRL 与核对状态、保存期间观测到的模式/版本、UTC 时间、字节数和 SHA256。应将两个文件一起归档。

配套文件在开始保存和正常停止时写入，保存过程中或异常终止时可能仅保留初始状态（`finished=false`），不能作为完整日志校验证据。正常结束的文件在监视器回放、命令行分析和 KF-GINS 运行前核对日志字节数与 SHA256；修改/裁剪日志后应保留原文件及其配套配置，给裁剪数据另行建立准确配置。无配套配置的旧日志仍可读取，但需人工核对比例；命令行分析默认按增量采集条件判断。配套配置不是传感器寄存器读回，也不是固件上报的比例。

默认“可开始采集”需要：IMU 近 3 秒约 200 Hz、两路 GNSS 消息新鲜、位置与航向均为 `SOL_COMPUTED / NARROW_INT` 且 GPS 时间 `FINE`、位置水平标准差不超过 0.20 m、高程标准差不超过 0.5 m、航向标准差不超过 2°、最近 5 秒航向基线变化不超过 0.1 m，且位置/航向连续稳定 5 秒、没有最近 5 秒的日志/固件链路错误。水平与航向阈值可以在界面修改，实测天线基线长度可选填；填入后还要求与报告基线相差不超过 0.1 m。这些数值是保守的采集门槛，按实际安装和精度目标调整。

“可开始采集”只表示**原始传感器采集条件**，不表示组合导航滤波器收敛。V2 固件把 IMU DRDY 与 GNSS PPS 捕获在同一个 TIM2 时基，并记录 UART 字节到达时刻；若 PPS 捕获超时、周期无效、捕获队列出错，或 `A` 行尚未连续建立 GPS 整秒配对，界面不会显示就绪。GPS 整秒归属仍依赖 UM982 消息延迟和 PPS 极性的核对，需用 `tools/time_sync_report.py` 和实测波形检查。

固件和上位机现在均按本次 200 Hz 数据的 COUNT 正常步长 312/313 检查跳帧。`test1.txt` 中有一条 GNSS 与 IMU 日志拼接损坏，上位机将其计为记录错误。若串口上位机处理队列溢出，也会使就绪条件暂时失败。

增量比例配置更新（2026-10-03）：新采集默认值为 `0x0048`，仍需核对并勾选确认；不是设备自动读回。必须先在 IMU 配置上位机设置角代码 4 / 速度代码 8，并烧录匹配的新固件。打开旧日志时沿用原 B/JSON 设置，不升级旧日志比例。
