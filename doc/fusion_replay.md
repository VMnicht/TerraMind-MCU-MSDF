# 二维组合导航离线回放

当前工具自动识别模式 2 角速度/加速度和模式 3 角增量/速度增量，保留原来的二维八状态融合模型。基于武汉大学 KF-GINS 的三维版本见 [kf_gins_replay.md](kf_gins_replay.md)，从 `tools/start_kf_gins_replay.bat` 启动。

双击 `tools/start_fusion_replay.bat`，选择 USART6 原始日志（例如 `terramind_20260927_171734.txt`），填写安装几何，然后点“运行融合”。也可运行 `python tools/fusion_replay.py "日志路径"`。缺少依赖时执行 `python -m pip install -r tools/requirements.txt`。回放界面可播放、暂停、拖动时间轴；在 EN 平面图上用滚轮围绕鼠标位置缩放，用左键拖动平移，点“重置视图”恢复全图。融合轨迹上的蓝点可悬停查看该帧时间、平面坐标和速度。视野内点过密时会抽样绘制标记，放大后会显示更多细节。可导出逐帧融合 CSV；高程不参与显示。

## 模式 3 增量输入

- 原始 `I` 记录中的模式自动识别，不需要手工选择。同一段不能混用模式 2/3。模式 2 保持原来的换算和预测流程，新增的模式 3 比例及板端标定开关对它不生效。
- `DLT_CTRL` 留空时，优先从日志 B 标定记录读取，否则从配套 `.capture.json` 读取。两者都没有时必须填写采集当时的实际值（例如 `0x0048`），不猜测量程。手填值与 B 或已核对采集配置冲突时拒绝运行。使用 G365PDF1 的增量系数，与监视器、KF-GINS 导入保持一致。
- “模式3：应用板端启动标定（B/JSON）”默认打开。使用已验证的板端 XYZ 陀螺静止均值，只扣角增量，不扣速度增量；该均值仍包含地球自转。B 与 JSON 相互核对，正常结束采集的 sidecar 校验日志字节数和 SHA256。仅 JSON 含标定时要求采集正常结束；缺少标定的旧日志需明确取消该开关才能回放。
- 一帧增量归属到以该帧时间戳结束的区间：`平均角速度 = 角增量 / dt − 板端静止均值`，`平均加速度 = 速度增量 / dt`。沿用二维预测器时按同一个区间积分；GNSS 历元在区间内部时拆分时长，总计只消耗一份增量，不使用上一帧增量外推下一帧。
- 有 PPS/DRDY 时使用硬件时间；只有足够 DRDY 时也用它确定 IMU 区间，但 GNSS 仍保留串口到达拟合。DRDY 不足时使用 MCU 帧间隔并提示。首帧间隔取中位数，首个完整 IMU 帧之前不进行增量预测；GNSS 更新限制在完整 IMU 时间范围内，不向日志尾部外推。
- 当前增量输入要求约 200 Hz，每帧间隔 4–6 ms、COUNT 步长 312/313，相邻有效 DRDY 序号连续。时间回退、丢帧、增量 int32 满量程、FLAG 错误位 `0x0101` 会报错，需分段或重新采集。采集结束时没有换行且字段不全的末行会明确提示并忽略；中间坏帧不会被静默跳过。
- 原有“前 3 秒静止标定”仍可独立使用，默认关闭。若同时应用 B，它在已扣板端均值的数据上估计残余陀螺均值和 X/Y 加速度均值，不再次扣同一份 B。只有通过原有静止判据才应用，不应因为板端启动时静止过就假定日志开头也静止。

安装 JSON 保留原有几何字段，新增可选 `imu_input`（`delta_ctrl`、`apply_startup_calibration`）和 `calibrate_static_imu`。旧几何 JSON 仍能导入。逐帧融合 CSV 列名和顺序保持不变；原始日志、B/JSON、采集器、板端数据输出均不改写。

**当前车辆的二维参数与 KF-GINS 不同。** 你的传感器 +Y 朝车前、+X 朝车左、+Z 向下，主天线在 IMU 左侧 15 cm，主→副天线朝车右。上位机启动已默认填写 `lever_x_m=+0.15`、`lever_y_m=0`、`heading_offset_deg=180`、`gyro_heading_sign=+1`、`imu_y_right_sign=+1`、`gnss_delay_ms=0`，仍可手动修改或导入其他安装 JSON。DLT_CTRL 默认留空按本次日志自动读取，模式 3 板端标定默认启用，额外前 3 秒标定默认关闭。这里显示/导出的航向是 **IMU +X（车左）方向**；车头航向为它加 90° 后取 0–360°。不要直接填入 KF-GINS 的右向杆臂 −0.15 m 和车头偏角 −90°。未知的前后杆臂仍需实际测量。

安装几何可在界面输入，并保存为 JSON，之后用“导入安装配置”复用。所有长度以米为单位。`lever_x_m`、`lever_y_m` 表示 **UM982 主天线相对 G365 测量中心**的位置，沿 IMU 的 +X 和 +Y 轴。`heading_offset_deg` 表示“IMU +X 的航向减去 UM982 主天线到副天线航向”，顺时针为正。`imu_y_right_sign` 为 +1 时视 IMU +Y 在 +X 的右侧，为 -1 时反向；`gyro_heading_sign` 为 +1 时 G365 Z 正角速度使航向顺时针增加。`gnss_delay_ms` 仅用于旧版 V1 日志，把 GNSS 历元相对于串口到达时间拟合出的时刻提前多少毫秒；有条件 PPS/DRDY 配对的 V2 回放使用 GNSS 历元本身，不用此值。当前旧日志的 Z 陀螺与 GNSS 顺时针航向变化呈正相关，因此默认 `gyro_heading_sign=+1`，但安装方向仍应实测核对。界面默认杆臂采用当前车辆安装；更换安装后应填写新的实测尺寸。

“启用前 3 秒静止 IMU 零位标定”默认关闭。勾选并重新运行融合后，程序取日志起始 3 秒 IMU 样本，检查采样覆盖、三轴角速度和水平加速度波动，并用同期 UM982 多普勒速度与位置排除缓慢匀速运动。通过检查后，扣除这段样本的 X/Y/Z 三轴角速度及 X/Y 加速度均值，界面显示具体数值；未通过时不扣除，界面给出原因。二维融合只使用 Z 轴角速度计算航向；X/Y 角速度虽然完成了零位估计与扣除，但目前不参与姿态或位置解算。当前阈值要求至少 400 帧 IMU、接近完整的 3 秒覆盖、足够的可靠 GNSS 速度，且 GNSS 最大速度不超过 0.35 m/s、首末位移不超过 0.15 m。请在打开日志采集前让设备静止至少 3 秒。X/Y 静态加速度均值可能同时包含安装倾斜造成的重力投影，它不是单独测得的传感器内部零偏；标定后若载体俯仰或横滚变化，二维模型仍会出现误差。导出 CSV 的 `gyro_bias_dps` 是滤波器估计的剩余 Z 轴零偏，不包含已预先扣除的界面显示值。

图中灰点是主天线原始 GNSS 位置，绿点是按输入的杆臂和航向修正到 IMU 测量中心的位置，蓝线和蓝点是二维 EKF 融合轨迹及其 IMU 帧位置，橙色箭头是当前融合航向。局部 EN 原点取首个有效 GNSS 位置，东向右、北向上。双天线航向直接观测 IMU +X 航向（加入输入安装偏角）；BESTNAVA 多普勒速度也参与滤波，包含旋转杆臂速度修正。200 Hz IMU 提供位置、速度、航向预测，10 Hz GNSS 更新位置、速度、航向，并估计平面加速度偏置和 Z 陀螺偏置。GNSS 解类型和标准差参与观测权重，位置噪声设置了保守下限。

界面显示本次日志的实际融合输出频率和 GNSS 位置更新频率。融合坐标随每个有效 IMU 帧输出，通常约 200 Hz；GNSS 观测约 10 Hz。蓝点在屏幕上按密度抽样，CSV 仍导出每个融合帧。GNSS 更新会使滤波位置发生即时修正，轨迹出现锯齿时应核对更新处的跳变、时间同步、实测杆臂和姿态变化；当前二维模型的 X/Y 陀螺轴不参与横滚俯仰解算。绘图没有对融合坐标做视觉平滑，以免掩盖这些误差。

旧版 V1 日志用 BESTNAVA 的 GPS 周/TOW 与 STM32 `mcu_ms` 做线性拟合，修正可见的时钟频率漂移；串口和接收机固定输出延迟仍未知。新版 V2 日志增加同一 TIM2 时基上的 IMU DRDY、GNSS PPS 和 UART 末字节记录。若有连续 PPS、可信的 GPS 整秒候选且至少 98% 的 IMU 帧能配对 DRDY，离线回放会使用硬件时基；否则回退到 V1 方法并显示原因。V2 的 GPS 整秒配对仍假设 BESTNAVA 对应历元的串口输出延迟小于 300 ms，须实测核对，具体见 `monitor_uart6.md`。该二维模型没有估计横滚、俯仰和重力投影，载体明显倾斜时会把部分重力当作平面加速度。曲线的平滑程度不等于定位精度；正式精度验证需要独立真值、实测安装几何和同步核验。
