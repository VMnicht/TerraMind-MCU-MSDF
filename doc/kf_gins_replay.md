# KF-GINS 三维组合导航离线回放

本工程把 [i2Nav-WHU/KF-GINS](https://github.com/i2Nav-WHU/KF-GINS) 作为 Git 子模块放在根目录 `KF-GINS/`，保持原算法源码不改动。该项目采用 GPL-3.0 许可，详情见 `KF-GINS/LICENSE`。首次获取本工程时运行 `git submodule update --init KF-GINS`。当前接入固定为所拉取的上游提交 `8291a93e49de513fe9d21f819500d39082ded611`。

## 轨迹参考点与航向诊断

融合蓝线默认显示“主天线（与 GNSS 同点）”：将 KF-GINS 输出的 IMU 位置加上本次解算的完整三维姿态旋转后的杆臂，再与 GNSS 主天线灰点比较。参考点下拉框可切回“IMU（原始解算位置）”，播放、缩放、平移、悬停坐标均继续可用。切换仅改变显示并重置视图范围，不重新解算；IMU 视图下灰点仍是主天线，非零杆臂会造成正常的位置差。坐标旁的速度和高程明确标为 IMU 结果。

“航向 / 残差曲线”显示融合航向与双天线换算车头航向，并绘制 `融合 − 双天线` 残差，按 ±180° 归一化。点击曲线可定位主窗口回放。对照按 GPS 历元对齐，在相邻有效航向间隔不超过 150 ms 时进行圆周插值；不外推、不跨缺口连线。当前参考标准差取两端较大值，仅用于显示，未作为新的滤波协方差。无有效对照时显示缺测，CSV 留空。

原“导出三维结果 CSV（IMU）”保留原有列、顺序及 IMU 数值，不受显示参考点影响。新增“导出诊断 CSV”同时提供 IMU / 主天线坐标、融合航向、双天线车头航向、参考标准差和航向残差。诊断数据固定使用该次运行的杆臂、偏角及姿态；修改输入框后需重新运行才改变结果。原始采集日志、B/JSON、二维回放和 KF-GINS 状态更新不因这些显示功能而改变。另有下述独立开关用于启用新增观测。

## 可选的离线航向 / 速度更新

界面提供“持续双天线航向更新（离线实验）”和“GNSS 多普勒速度更新（含杆臂）”两个开关，当前车载调优预设默认均打开。均关闭时仍运行原版 `KF-GINS` 可执行文件；任一打开时运行独立的 `tools/kf_gins_aided` 程序。旧安装 JSON 无需增加字段，读取时两个开关默认为关闭；新 JSON 保存 `heading_aiding` / `velocity_aiding`。开关变化只对下一次运行生效，当前结果的说明不会被改变。

先运行 `powershell -ExecutionPolicy Bypass -File tools/build_kf_gins_aided.ps1` 编译并自测增强程序，输出在 `build-navigation/aided/Release/`。增强程序复用板端封装内的完整双精度 21 状态内核、惯导机械编排、噪声和 IMU 零偏/比例因子估计；读取同一份 YAML，保留所有初始标准差及自定义噪声参数。核心头文件只增加离线访问声明，增强代码未加入固件工程，也未接入实时任务。上游子模块不改动。

- **航向**：只用实际 `UNIHEADINGA` GPS 历元，要求整数固定解、标准差不超过 5°，基线长度相对本段固定解中位数偏差不超过 `max(5 cm, 20%)`。假设天线基线在车体水平面，方向来自安装偏角；先用完整姿态旋转基线，再预测导航系方位角，不把俯仰/横滚时的基线方位直接等同于车头欧拉角。标准差下限 0.5°；一维 NIS 门限 10.83。诊断界面中的插值航向不会进入滤波。
- **速度**：解析 BESTNAVA 的水平速度、航迹角、上向速度及垂直/水平速度标准差，转为 NED 速度。要求有效 DOPPLER_VELOCITY、有限值、水平标准差 ≤1 m/s、垂直标准差 ≤2 m/s。当前增量仅接受速度 latency/age 为零的历元；非零值明确拒绝并计数，尚未添加跨历元速度对齐。水平标准差作为 N/E 各轴标准差，三轴下限 0.05 m/s；三维 NIS 门限 16.27。
- **旋转杆臂**：速度预测包含 `v_IMU + C_b^n(ω_ib^b × l^b) − ω_ie^n × (C_b^n l^b)`，使用补偿后的角增量计算角速度，并包含姿态、陀螺零偏和比例因子对应的观测偏导。不会在转弯时把主天线速度直接当成 IMU 速度。
- 位置、速度、航向按 GPS 历元合并，在原有上一帧/当前帧/帧间插值三种分支处理；同历元共享一次误差反馈。新观测采用条件创新（扣除已累计误差状态）做 NIS 检查。GNSS 位置原更新逻辑不变。初始化已使用的首历元可能早于种子 IMU，因此不再次更新；质量通过数会比实际采用数多 1。
- 保留缺测时的惯导预测，拒绝观测不会中止正常传播。不同观测历元挤在同一 IMU 区间时明确报错，不静默丢弃；现有两份日志为 200 Hz IMU / 同步 10 Hz GNSS，可正常运行。观测间未知交叉相关性未建模，采用标准差下限避免直接使用过小的接收机方差；这不能替代实际噪声标定。

2026-10-03 的 `160516` / `160557` 已分别跑原模式、仅航向、仅速度、两者同时四组。安装参数固定为前 +Y / 右 −X / 下 +Z，杆臂 `[0,-0.15,0] m`，航向偏角 −90°，应用原 B 标定，噪声 YAML 未针对某段调参。弯道判定固定为 IMU 车体 Z 角速度绝对值 >10°/s，位置统一换算到主天线，在 GNSS 历元比较：

## 首次准备

1. 安装 Python 依赖：`python -m pip install -r tools/requirements.txt`。
2. 用 Visual Studio C++ 桌面开发工作负载和 CMake 编译原算法：在工程根目录运行 `powershell -ExecutionPolicy Bypass -File tools/build_kf_gins.ps1`。此脚本生成 `KF-GINS/bin/Release/KF-GINS.exe`，只需编译一次。当前工作站已编译成功。
3. 默认车载预设还需编译增强程序：`powershell -ExecutionPolicy Bypass -File tools/build_kf_gins_aided.ps1`。
4. 双击 `tools/start_kf_gins_replay.bat`，或运行 `python tools/kf_gins_replay.py [USART6日志.txt]`。

在界面选择一份 USART6 原始日志，默认勾选“应用板端启动标定”。界面显示从 B / 配套 JSON 读取的三轴静止均值、标定时长和比例配置；核对 KF 输入参数后点击“运行融合”。下方与二维版共用 EN 轨迹、GNSS 位置点、播放/暂停、缩放、拖动、悬停和时间轴；当前帧还显示高程、横滚和俯仰。点击“导出三维结果 CSV”得到逐 IMU 帧的位置、三维速度和姿态。EN 图仅用于平面浏览，高程数值显示在状态栏和 CSV 中。算法原生结果仅在本次计算的临时目录中生成，界面导出 CSV 后可长期保存。

上位机启动默认采用已确认的车辆配置：`DLT_CTRL=0x0048`，前/右/下映射 `+y/-x/+z`，主天线前/右/下杆臂 `[0,-0.15,0] m`，航向偏角 `-90°`，初始横滚/俯仰均为 `0°`，初始航向留空自动读取双天线，无 PPS 时的提前量为 `0 ms`。仍可手动修改及导入安装 JSON；选择日志时继续读取该次采集记录的 DLT_CTRL，避免历史日志被错误套用新比例。

## 采集要求

- 当前固件启动默认模式 3（`imu_capture_config.h`），旧固件需切换或重新烧录。整段日志保持模式 3。回放器拒绝混有模式 2 的日志，不会把角速度/加速度误作角增量/速度增量。
- 在实际 G365PDF1 读取并核对 `DLT_CTRL`，再以 `App_ImuSetDeltaCtrl(实际值)` 设置固件；界面填写同一寄存器值。新默认 `0x0048` 是待配置的动态采集值，仍需与本次日志采集配置一致；旧日志保留原 B/JSON 比例，不能直接套用新默认值。代码高/低半字节分别控制角增量/速度增量比例，见 `doc/g365_uart_modes.md`。
- 新采集器附带 `日志名.txt.capture.json`。选择日志时自动加载其中的 DLT_CTRL，并显示人工核对状态；运行前验证正常结束日志的字节数和 SHA256。回放参数与采集时已核对值冲突时拒绝运行，避免静默换算错误。无配套配置的旧日志可从 B 读取标定；没有 B 或有效 JSON 标定的旧日志，必须明确取消“应用板端启动标定”才能分析原始输入，并提示缺少采集时核对记录。配套文件未正常结束或比例未确认时，会在结果中给出提示。
- 新固件完成启动静止统计后才发送数据，`B,1,...` 记录保存启动统计均值和标准差，`I` 始终是未扣均值的原始增量。回放默认读取并验证 B 格式、模式/比例与本段标定一致性；有不同标定结果必须分段。B 与 JSON 同时存在时核对两者；只有 JSON 含标定时，要求正常结束的采集记录及字节数/SHA256 校验通过。生成临时 IMU 输入时执行 `delta_angle_rad -= stationary_rate_rad_s * dt`，先在传感器 XYZ 轴扣除，再作前右下映射；速度增量不变，原始日志和 JSON 不改写。间隔优先使用相邻 DRDY；缺少完整相邻 DRDY 时用回放时间差，首帧用中位间隔并提示。COUNT/DRDY 序号不连续或补偿间隔超出 4–6 ms 时拒绝运行。B 中的均值含地球自转，且未记录标定时完整姿态：当前采用与监视器一致的“去静止均值”输入，并非已分离地球自转的真实传感器零偏标定。应用时覆盖临时 YAML 的 `initgyrbias` 为零残差初值，避免再次扣除原来的陀螺零偏；21 状态、噪声模型及后续残余误差估计保持不变。
- 保留 `I`、`T`、`P`、`R`、`A`、`N` 原始记录。建议采集前静止至少 30 秒，检查 `tools/time_sync_report.py` 给出的 PPS、DRDY、GNSS 时间配对；GNSS 应输出 `BESTNAVA` 和 `UNIHEADINGA`。同一 TIM2 时基的 PPS/DRDY 条件配对成立且至少 98% 的 IMU 有 DRDY 时间戳时采用硬件时间，否则退回 MCU/GPS 串口到达拟合并在界面警告。PPS 极性、GPS 时间基准以及整秒归属仍需实测核对。
- 增量 IMU 应约为 200 Hz，日志需至少 20 帧模式 3、3 条有效位置，IMU 起点后 1.5 秒内需有位置，处理区间内至少两次 GNSS 更新。相邻 IMU 时差超过 100 ms、GPS 跨周、时间非递增、IMU 模式混用会中止计算。采集长时间数据时也应检查 `S/H` 错误计数与 COUNT 跳变。

## 安装与初始状态

### 动态采集的有效性

离线导入拒绝角/速度增量出现 int32 正负满量程或 FLAG 的错误/超量程位（0x0101）置位的日志，不静默删除坏帧或继续融合。改变回放比例不能恢复传感器已经截顶的数据。

2026-10-03 的 `terramind_20261003_145805.txt` 有 673 帧 Z 角增量达到 int32 满量程，4795 帧 FLAG 为 0xFEFD。实际 DLT_CTRL=0x0008 的角增量代码为 0，在 200 Hz 下可表示约 ±49.65°/s，不能覆盖这次较快转弯。若采用角增量代码 4、速度代码仍为 8，则 DLT_CTRL 低字节为 0x48，对应同频率下约 ±794.38°/s 的表示范围。必须先正确配置物理传感器并读回，再同步 MCU/采集参数、重新上电静止标定并采集；不能只改软件默认值，原日志也不能改标为新比例。

本次安装说明：车前 +Y、车右 −X、车下 +Z；主→副天线朝车右，所以自动双天线初始航向偏角为 −90°；IMU 在主天线右侧 15 cm，所以主天线相对 IMU 的右向杆臂为 −0.15 m，前向/下向按实测填写。手填初始航向则应直接填车头航向，偏角只作用于自动读取双天线航向的路径。

KF-GINS 使用车体**前、右、下**右手系，导航系为**北、东、下**。界面三个轴映射写法为 `+x`、`-y` 等，必须是保持右手系的三个不同轴。先实测 IMU 轴向，再填主天线相对 IMU 测量中心的三轴杆臂（米）。初始横滚/俯仰需要按安装姿态或静态标定填写；默认 0° 只适合水平安装。空白初始航向取起点附近 250 ms 内的有效 `UNIHEADINGA` 主→副天线航向，再加安装偏角；也可输入已经换算为车体前向的初始航向。有效多普勒速度用于初始北、东、下速度，否则以 0 初始化并提示。

GNSS 位置来自 `BESTNAVA`；其海平面高加大地水准面起伏得到 KF-GINS 所需椭球高。经纬度标准差和高程标准差传入 KF-GINS，设有 0.03/0.05 m 最低值。原模式的连续更新只使用 GNSS 位置；可通过上述开关启用持续速度/航向更新。默认滤波参数取 `tools/config/kf_gins_g365_vehicle.yaml`；“原版对照参数”切回 `KF-GINS/config/kf-gins.yaml` 并关闭航向/速度更新。界面可选择自定义 YAML 模板，工具替换文件路径、时间、初始状态和杆臂；启用启动补偿时还将初始陀螺残余零偏设为 0，取消勾选则保留模板中的陀螺零偏初值。参数可保存/导入 JSON。

G365 模式 3 的原始增量按 `DLT_CTRL` 比例换算，角增量转为弧度、速度增量转为 m/s；输入以 GPS 周内秒标时。V2 条件硬件同步无法建立时的 `gnss_delay_ms` 可用实测串口/解算延迟校正，默认 0 并不代表没有延迟。结果是估计值而非独立真值；正式精度评估仍需独立参考轨迹与实测安装/同步参数。
