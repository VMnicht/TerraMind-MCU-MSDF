# KF-GINS 三维组合导航离线回放

本工程把 [i2Nav-WHU/KF-GINS](https://github.com/i2Nav-WHU/KF-GINS) 作为 Git 子模块放在根目录 `KF-GINS/`，保持原算法源码不改动。该项目采用 GPL-3.0 许可，详情见 `KF-GINS/LICENSE`。首次获取本工程时运行 `git submodule update --init KF-GINS`。当前接入固定为所拉取的上游提交 `8291a93e49de513fe9d21f819500d39082ded611`。

## 首次准备

1. 安装 Python 依赖：`python -m pip install -r tools/requirements.txt`。
2. 用 Visual Studio C++ 桌面开发工作负载和 CMake 编译原算法：在工程根目录运行 `powershell -ExecutionPolicy Bypass -File tools/build_kf_gins.ps1`。此脚本生成 `KF-GINS/bin/Release/KF-GINS.exe`，只需编译一次。当前工作站已编译成功。
3. 双击 `tools/start_kf_gins_replay.bat`，或运行 `python tools/kf_gins_replay.py [USART6日志.txt]`。

在界面选择一份 USART6 原始日志，核对 KF 输入参数，点击“运行融合”。下方与二维版共用 EN 轨迹、GNSS 位置点、播放/暂停、缩放、拖动、悬停和时间轴；当前帧还显示高程、横滚和俯仰。点击“导出三维结果 CSV”得到逐 IMU 帧的位置、三维速度和姿态。EN 图仅用于平面浏览，高程数值显示在状态栏和 CSV 中。算法原生结果仅在本次计算的临时目录中生成，界面导出 CSV 后可长期保存。

## 采集要求

- 当前固件启动默认模式 3（`imu_capture_config.h`），旧固件需切换或重新烧录。整段日志保持模式 3。回放器拒绝混有模式 2 的日志，不会把角速度/加速度误作角增量/速度增量。
- 在实际 G365PDF1 读取并核对 `DLT_CTRL`，再以 `App_ImuSetDeltaCtrl(实际值)` 设置固件；界面填写同一寄存器值。默认 `0x0008` 来自 2026-10-02 上位机设备读回，仍需与本次日志采集配置一致，并非历史数据自带的证明。代码高/低半字节分别控制角增量/速度增量比例，见 `doc/g365_uart_modes.md`。
- 新采集器附带 `日志名.txt.capture.json`。选择日志时自动加载其中的 DLT_CTRL，并显示人工核对状态；运行前验证正常结束日志的字节数和 SHA256。回放参数与采集时已核对值冲突时拒绝运行，避免静默换算错误。无配套配置的旧日志仍可按手动参数运行，并提示缺少采集时核对记录。配套文件未正常结束或比例未确认时，会在结果中给出提示。
- 新固件完成启动静止统计后才发送数据，`B,1,...` 记录保存启动统计均值和标准差，`I` 始终是未扣均值的原始增量。回放读取并验证 B 格式、模式/比例与本段标定一致性；有不同标定结果必须分段。B 中的均值含地球自转，且未记录标定时完整姿态，因此当前离线工具不会直接用它替换 KF-GINS 真正的陀螺零偏初值，会给出相应提示。原有噪声模型、21 状态及零偏估计能力保持不变。
- 保留 `I`、`T`、`P`、`R`、`A`、`N` 原始记录。建议采集前静止至少 30 秒，检查 `tools/time_sync_report.py` 给出的 PPS、DRDY、GNSS 时间配对；GNSS 应输出 `BESTNAVA` 和 `UNIHEADINGA`。同一 TIM2 时基的 PPS/DRDY 条件配对成立且至少 98% 的 IMU 有 DRDY 时间戳时采用硬件时间，否则退回 MCU/GPS 串口到达拟合并在界面警告。PPS 极性、GPS 时间基准以及整秒归属仍需实测核对。
- 增量 IMU 应约为 200 Hz，日志需至少 20 帧模式 3、3 条有效位置，IMU 起点后 1.5 秒内需有位置，处理区间内至少两次 GNSS 更新。相邻 IMU 时差超过 100 ms、GPS 跨周、时间非递增、IMU 模式混用会中止计算。采集长时间数据时也应检查 `S/H` 错误计数与 COUNT 跳变。

## 安装与初始状态

KF-GINS 使用车体**前、右、下**右手系，导航系为**北、东、下**。界面三个轴映射写法为 `+x`、`-y` 等，必须是保持右手系的三个不同轴。先实测 IMU 轴向，再填主天线相对 IMU 测量中心的三轴杆臂（米）。初始横滚/俯仰需要按安装姿态或静态标定填写；默认 0° 只适合水平安装。空白初始航向取起点附近 250 ms 内的有效 `UNIHEADINGA` 主→副天线航向，再加安装偏角；也可输入已经换算为车体前向的初始航向。有效多普勒速度用于初始北、东、下速度，否则以 0 初始化并提示。

GNSS 位置来自 `BESTNAVA`；其海平面高加大地水准面起伏得到 KF-GINS 所需椭球高。经纬度标准差和高程标准差传入 KF-GINS，设有 0.03/0.05 m 最低值。KF-GINS 的连续观测更新**只使用 GNSS 位置**；多普勒速度和双天线航向不会在后续滤波中更新，因此航向/姿态收敛不能按二维版的结果理解。滤波器噪声和零偏参数取 `KF-GINS/config/kf-gins.yaml`；界面可选择自定义 YAML 模板，工具只替换文件路径、时间、初始状态和杆臂。参数可保存/导入 JSON。

G365 模式 3 的原始增量按 `DLT_CTRL` 比例换算，角增量转为弧度、速度增量转为 m/s；输入以 GPS 周内秒标时。V2 条件硬件同步无法建立时的 `gnss_delay_ms` 可用实测串口/解算延迟校正，默认 0 并不代表没有延迟。结果是估计值而非独立真值；正式精度评估仍需独立参考轨迹与实测安装/同步参数。
