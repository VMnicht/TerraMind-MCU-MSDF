# KF-GINS H7 独立模块与接入准备

## 当前交付边界

模块位于 `TerraMind_FW/Navigation/`，公共接口为 `navigation.h`，可从 C/C++ 调用。
完整算法已加入 Keil 的 `Navigation (dormant library)` 组，**尚未接入实际采集流程**：

- 没有创建导航任务、全局导航实例或静态初始化入口。
- 没有改动 `app_tasks`、传感器回调、TIM2/PPS、UART、DMA、时钟或 FreeRTOS 配置。
- 没有改动 `Monitor_*`、日志类型/字段/波特率或上位机的保存与回放代码。
- 模块没有 `printf`、iostream、HAL、RTOS、UART 依赖；任何 API 都不会发送日志。
- 未被调用的导航函数会被链接器移除。当前采集程序不分配导航上下文，也不运行导航计算。

H7 最高 240 MHz 是后续性能验收上限。本次没有修改工程现有主频，没有烧录设备；
主机测试耗时不能换算为 H7 的保证输出频率。

## 保留的算法

保留 21 维误差状态、18 维驱动噪声、全程 double、双子样圆锥/划桨补偿、
地球/重力模型、零偏/比例因子一阶高斯—马尔科夫过程、杆臂观测模型、
全部交叉协方差、每个 IMU 历元的状态与协方差传播、GNSS 历元插值、
Joseph 协方差更新及全部误差反馈。

GNSS 连续更新仍使用位置；航向与多普勒速度可用于初始化，与现有上游能力一致。
来源及适配差异见 `TerraMind_FW/Navigation/UPSTREAM.md`。上游子模块保持不变。

## 内存与执行约定

上下文由调用方提供内存，使用 `Nav_ContextSize()` / `Nav_ContextAlignment()` 查询。
初次 ARM 编译的上下文约 54 KiB（55,064 字节，8 字节对齐；主机 ABI 略有不同），
包含完整内核工作区、256 帧 IMU 队列、32 条 GNSS 队列及结果/统计。
不要把上下文放在当前 6 KiB 任务栈，也不要从当前 512 B C 库堆分配。
后续可预留 64 KiB 静态内存，构造时检查尺寸；更改容量或编译选项后重新核对。

大矩阵工作区在上下文内，固定尺寸 Eigen 内核仍有小矩阵/乘法临时栈空间。
接入时必须测量任务栈峰值，不能认为“固定矩阵”意味着零栈开销。
测试编译开启 `EIGEN_NO_MALLOC` 和断言；正常路径不调用堆分配。

所有涉及同一上下文的 API 由**同一个任务**调用，或由调用方进行外部串行化。
本模块的队列不是 ISR 与任务并发队列。中断只捕获/接收，完整样本在任务中转交。
`Nav_Construct()` 对一块存储只调用一次；重复配置用 `Nav_Initialize()`。
`Nav_Destroy()` 之后，方可再次在同一块存储构造。

## 配置与数据契约

`Nav_DefaultConfig()` 的初始不确定度与 IMU 噪声已同步
`tools/config/kf_gins_g365_vehicle.yaml` 的车载调优参数（2026-10-03），
杆臂默认零，**必须按安装实测填写**。默认输出请求为 100 Hz，延迟缓冲为 0.2 s；
0.2 s 只是调试初值，不是已测得的 UM982 延迟上界。

此次仅同步参数，GNSS 连续更新仍然只有位置，没有加入离线增强的持续航向或多普勒速度更新。
三项变化及单位换算如下：

| 配置项 | 原板端值 | 当前板端值 | 离线 YAML 对应值 |
| --- | --- | --- | --- |
| `initial_std.accel_bias` 三轴 | 0.0025 m/s² | 0.1 m/s² | `initbastd: [10000,10000,10000]` mGal |
| `initial_std.attitude` 横滚/俯仰/航向 | 0.5°/0.5°/1° 转 rad | 2°/2°/3° 转 rad | `initattstd: [2,2,3]` ° |
| `accel_vrw` 三轴 | 0.24/60 m/s/√s | 0.5/60 m/s/√s | `vrw: [0.5,0.5,0.5]` m/s/√h |

`accel_bias_std`（过程模型）仍为 0.0025 m/s²，相关时间仍为 3600 s；
它与 `initial_std.accel_bias`（初始估计不确定度）现在独立设置。
所有实际零偏初值仍为零，未写入两份日志拟合出的偏差。陀螺、比例因子及其余噪声参数保持原值。
轴映射、杆臂和实际导航初值仍由接入层显式配置，本次没有创建接入层或改变实际采集流程。

- 纬经度、RPY 用 rad；位置高度用椭球高 m；速度为 NED m/s。
- 角增量 rad、速度增量 m/s；零偏分别 rad/s、m/s²；比例因子无量纲。
- `initial_std.position` 是 NED 米，不能填纬经度标准差弧度。
- ARW 使用 rad/√s，VRW 使用 (m/s)/√s，相关时间使用秒；不能直接复制 YAML 的小时单位。
- `Nav_Initialize(config, seed)` 的初始状态必须对应 `seed.time_s`；seed 是该历元结束的完整 IMU 增量，
  用于下一帧双子样补偿，只做初始化误差补偿，不作为新帧再传播一次。
- 所有时间（IMU、GNSS、`Nav_Process(now)`、`Nav_PollOutput(now)`）必须位于同一个连续秒时间轴。
  可以采用从启动基准起的 GPS 秒，跨周由外层展开；不要混入串口到达时间或 HAL 毫秒。
- 每帧 `dt_s` 必须与相邻 IMU 时间差一致。重复/倒序、非法值会返回错误；超过 `max_imu_gap_s`
  会锁定故障。传感器 COUNT 跳变与数据有效性仍需外层检查，不能把缺失增量伪造成正常长积分。
- GNSS 必须按历元递增投递；传入前由外层检查 CRC、解状态、时间有效性与新鲜度。
- 与上游一样，每个 IMU 区间最多一个 GNSS 更新；超出会返回 `NAV_OBSERVATION_DENSITY` 并故障，
  不会覆盖未处理观测。目标 200 Hz IMU / 10 Hz GNSS 满足这一条件。

适配函数：

| API | 行为 |
| --- | --- |
| `Nav_G365Delta` | 只接受模式 3，验证右手轴映射，从原始 int32 直接换算 double 增量 |
| `Nav_GnssDegrees` | 度转弧度、海平面高加起伏转椭球高；沿用桥接工具的 0.03/0.05 m 标准差下限 |
| `Nav_InitialFromAntenna` | 按给定 RPY、角速度和杆臂，把天线初始位置/速度换到 IMU 中心 |

G365 的模式与 DLT_CTRL 必须和真实传感器配置一致，函数不会写寄存器。
航向安装偏角、双天线航向/多普勒初始速度选择由外层完成；也可以直接填写全部初始状态。

## 调用顺序（尚未添加到实际 App）

1. 启动阶段准备静态内存，调用 `Nav_Construct()`；建立正确同步和初始化状态后调用 `Nav_Initialize()`。
2. 将解析器收到的**每个**有效样本通过 `Nav_PushImu()` / `Nav_PushGnss()` 投递。
   不能轮询 `GetLatest()` 替代逐帧交付。先排空当轮传感器输入，再调用处理函数。
3. `Nav_Process(now_s, max_samples, &processed)` 在 `now_s-buffer_delay_s` 之前处理最多指定数量样本。
   它不等待、不睡眠；循环次数由调用方控制，便于安排调度预算。
4. `Nav_PollOutput(now_s, &output)` 返回 1 时取得新的到期快照。调用方决定展示/发送到哪里。
5. 定期读取 `Nav_GetStats()`；完整协方差可用 `Nav_GetCovariance()` 按行主序读取。

延迟缓冲只改变处理滞后，不修改传感器的测量时间。
在缓冲范围内晚到的 GNSS 会被按测量历元处理；已经超过处理状态时刻的旧观测返回
`NAV_LATE_GNSS`、增加计数并设置粘滞标志。首版不实现历史回退重传播。
增加缓冲时长之前必须核对 IMU 队列容量，初始化也会按 seed 周期检查容量约束。

PPS 与 DRDY 的硬件时刻配对、时钟锁定/失锁、时间轴连续化由现有同步层和未来接入层负责，
本模块不会仅凭收到一个 `NavImu` 就宣称硬件已同步。当前 `TimeSync_MatchDrdy()` 被日志模块消耗；
接入时应先统一配对再分发，不能让导航和日志分别调用一次。不得改变现有 `T` 行对应关系。

## 可调输出与日志兼容

`Nav_SetOutputRate(context, hz)` 支持 0 或 [1,200] Hz，可在运行中修改，不重置滤波器。
0 仅关闭发布。计算仍逐帧进行。常用 10/20/25/40/50/100/200 Hz；其他频率的发布时刻受 5 ms
输入间隔量化。修改频率后下一份新快照可立即发布。

调度使用绝对时间推进；若调用方错过发布时隙，只返回最新的一份，不补发突发包，也不重复
同一结果序号。`skipped_output_slots` 记录错过的时隙，不表示滤波丢了 IMU。

`NavOutput` 包含完整导航状态、12 项 IMU 误差、21 项标准差、序号、测量时刻、发布时间、
结果年龄、最近 GNSS 更新时刻和异常标志。`Nav_GetLatest()` 是非调度快照查询；其中
`publish_time_s/age_s` 不作为有效发送时间使用，只有 `Nav_PollOutput()` 填入这些字段。

**本次不实现串口发送器，也不把任何二进制字节混入原 USART6 文本日志。**
现有 V/I/N/S/D/P/T/R/H/A 数据仍按原流程输出，PC 保存和回放程序无需更新。
未来实时接入优先把导航结果交给独立通道或应用消费者；如果共用 USART6，须另行设计可兼容的
记录协议、带宽与优先级，并用原始日志回放回归验收。不得通过丢原始 IMU/GNSS 日志给结果让路。

独立串口的对外数据格式已约定为 [导航串口协议 v1](navigation_output_protocol_v1.md)：
固定 80 字节，包含位置、速度、RPY、四元数和 RTK 状态，默认 100 Hz、DMA 发送。
该文档用于固件与上层先行对接；发送器及公开快照中的四元数字段尚未实现，实际采集接入边界不变。

## 统计与故障

统计包含输入/处理/输出计数、队列深度与峰值、迟到 GNSS、输入错误、溢出、数值故障、
输出时隙跳过、状态/发布时间和最大结果年龄。用相邻统计快照的计数差/时间差计算实际频率。

可用 `Nav_SetCycleClock()` 注入读取 `DWT->CYCCNT` 的函数，模块不自行启用 DWT 或修改时钟。
记录完整单帧处理（含快照生成）的上次/最大/累计周期，以及四种更新路径各自的计数和最大周期。
无符号减法支持一次计数器回绕，单次测量不得跨越整个 32 位计数周期。启用时的中断抢占会包含
在测得的耗时内；不是不受中断影响的纯内核周期数。

队列溢出、IMU 长间隔、同区间观测过密、协方差/状态非有限值及奇异新息会锁定故障，
停止处理及定时发布。所有 API 返回值都应被调用方检查。`issue_flags` 自初始化起粘滞，
显式重新初始化才清除。`Nav_GetLatest()` 仍可取得带故障标志的最后良好快照用于诊断。

## 离线自测

在工程根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test_navigation.ps1
python -B -m unittest discover -s tests -p 'test_*.py' -v
```

第一条只在 `build-navigation/` 生成主机程序和对照数据：

- 独立进程链接未修改的上游核心，产生每帧参考状态和全部协方差。
- 比较 6000 帧合成增量（30 s，全部更新分支、非零初始零偏/比例因子、GNSS 中断与恢复）。
- 比较上游真实数据前 12000 个处理历元（60 s），使用其配套初始化参数。
- 验证延迟输入、调频/关闭输出、不重复发布、队列溢出、错误数据、时间连续性及计时钩子。
- C 编译单元检查公共头文件确实可由 C 使用。
- 一并运行原有 USART6 DMA 队列与 TIM2 同步捕获的主机回归测试。

详细差异见 `build-navigation/Testing/Temporary/LastTest.log`。这些测试检查移植等价性，
不把估计轨迹当作独立真值，也不证明上板 100 Hz 输出已达标。
用户提供的 `terramind_20260927_171734.txt` 为模式 2，本次没有把它伪装成增量数据用于精度验证。

## 后续实际接入验收

1. 读取并核对传感器增量模式、DLT_CTRL、安装轴向、杆臂及初始化状态。
2. 验证 PPS/DRDY 极性、GPS 整秒归属、时基误差和 GNSS 最大延迟，确定缓冲长度。
3. 给导航配置静态内存、独立任务与合适任务栈；不在中断或日志回调里计算 EKF。
4. 接通逐帧输入、唯一时间配对和结果消费者；USART6 原始日志继续保持兼容。
5. 在不超过 240 MHz 的实际配置下测四种路径耗时、任务栈、队列积压和结果年龄；
   按 20/50/100 Hz 等输出设置调试，不通过降低协方差传播频率满足吞吐。
6. 长时间记录原始数据并回放对照，确认模式切换、失锁、断流和恢复都有明确状态。

上述步骤仍未对真实采集流程执行。当前交付是可编译、可离线验证的独立算法模块。
